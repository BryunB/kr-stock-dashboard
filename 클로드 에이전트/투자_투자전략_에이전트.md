## 한 줄 요약

**V1은 LLM을 쓰지 않는다.** 예측 신호에 임계값 규칙을 적용해 매매를 결정하는 순수 함수(제안)와,
그 제안을 다시 검증하는 결정론적 코드(승인) — 둘 다 코드지만 역할은 나눠져 있다.

## 왜 LLM이 아니라 규칙 기반인가 (설계 변경 이력)

원래 설계는 Claude API로 판단하는 LLM 에이전트였다. **유료 서비스라 지금은 키 발급 없이
진행하겠다**는 사용자 결정에 따라 규칙 임계값 엔진으로 바꿨다. 이건 폐기가 아니라 유예다 —
`decide_trades()` 함수의 경계(입력: 신호+보유현황, 출력: 매매 액션 리스트)를 그대로 유지해뒀으므로,
나중에 키를 발급받으면 이 함수 **내부만** LLM 호출로 바꾸면 된다. 호출부([[투자_실행_스케줄러]]),
가드레일, [[투자_포트폴리오_원장]], [[투자_성과리포팅_UI]] 어느 것도 손댈 필요가 없다 — 가드레일이
"제안을 다시 검증"하는 구조라 제안이 규칙에서 나오든 LLM에서 나오든 똑같이 동작하기 때문이다.

부수 효과: **외부 API 호출도, 신규 의존성도, API 키 관리도 전혀 없어졌다.** `dataclasses`(표준
라이브러리)만으로 매매 액션을 표현한다.

## ② 매매 규칙 엔진 파트

**한다**
- [[투자_가격예측_에이전트]]가 준 신호(예측수익률·RSI·뉴스감성·방향적중률)와 현재 보유 현황에
  임계값 규칙을 적용해 매수/매도 후보를 뽑는다.
- 각 매매마다 **조건을 그대로 조립한 한국어 근거 문장**을 만든다 (LLM 자유 생성이 아니라
  결정론적 템플릿 — 그래도 "왜 샀는지" 투명하게 보여주는 목적은 동일하게 달성한다).

**지켜야 할 것**
- 순수 함수로 짠다 — 같은 입력엔 항상 같은 출력. 외부 상태(오늘 날짜, 랜덤값 등)에 의존하지 않는다.
- 매수 조건(예측수익률·방향적중률·RSI·뉴스감성 임계값)과 매도 조건(손절·익절·신호소멸·RSI과매수)을
  분리해서 각각 테스트할 수 있게 짠다.
- 임계값은 전부 `TRADING_RULES` 상수 딕셔너리 하나에 모은다 — 6장 리스크 정책 표와 정확히 같은 값.

## ③ 리스크 가드레일 파트

**한다**
- 규칙 엔진이 제안한 각 액션을 다시 검증해 **위반 시 항상 거부한다 — 수량을 깎아서 통과시키지
  않는다** (현금 한도, 보유 수량, 종목당 비중, 동시보유 수, 하루 거래 횟수).
- 거부한 액션은 조용히 버리지 않고 사유와 함께 로그로 남긴다(`rejected` 리스트, 사유 문자열 포함).

**왜 수량을 축소하지 않고 거부만 하는가** — 축소는 "그럴듯하게 고쳐서 통과"시키는 것이라 규칙
엔진 쪽 버그(잘못된 사이징 계산 등)를 조용히 감춘다. 거부하면 그 버그가 로그에 그대로 드러나서
다음 실행 전에 고칠 기회가 생긴다.

**왜 규칙 엔진과 또 분리하는가** — 규칙 엔진도 같은 `TRADING_RULES`를 참조하므로 원칙적으로는
위반이 안 나와야 맞다. 하지만 **로직 자체의 버그**(부호 반전, 여러 매수가 겹쳐 현금이 실제로는
모자란 경우 등)는 여전히 가능하다. "이 신호로 뭘 살지 정하는 로직"과 "정해진 게 한도를 넘는지
확인하는 로직"을 분리해두면 두 로직을 독립적으로 테스트할 수 있다는 게 핵심 이점이다 — LLM이
있든 없든 이 분리 자체는 유효하다.

## 테스트할 때 주의

- 외부 API가 없으므로 **모킹이 필요 없다.** 합성 신호 데이터를 직접 만들어 쓴다.
- 정상 케이스보다 **경계값**을 더 촘촘히 본다 — 임계값보다 정확히 1틱 위/아래인 입력에서 매수·매도
  판정이 뒤집히는지, 리스크 한도를 정확히 넘기는 입력에서 가드레일이 실제로 거부하는지.
