## 배치 방식 (사용자 확정 — 기존 `app.py`는 건드리지 않는다)

기존 `app.py`는 지금 지인에게 공유 중인 배포이므로 **한 글자도 수정하지 않는다.** 대신
`demo_app.py`(신규)라는 새 진입점을 만들어 `st.navigation` + `st.Page`로 기존 `app.py`와 이
페이지를 묶는다 — `st.Page("app.py")`처럼 기존 스크립트를 그대로 페이지로 재사용할 수 있어서
`app.py` 쪽 변경이 전혀 필요 없다. Streamlit Cloud에 `demo_app.py`를 main file로 하는 **새
배포**를 하나 더 만들면 기존 링크는 그대로 살아있고 데모용 링크가 하나 더 생긴다. 상세는 PRD 5.6.

## 가장 중요한 제약: 읽기 전용

**이 페이지에는 매매를 유발하는 코드가 단 한 줄도 들어가면 안 된다.** 방문이 매매를 일으키면
[[투자_실행_스케줄러]]의 실행/조회 분리가 무너지고, 방문자가 여럿일 때 중복 매매가 발생한다.
`portfolio.py`의 읽기 함수만 호출하고, 쓰기 함수·[[투자_투자전략_에이전트|매매 규칙 엔진]]·`git` 명령은 import조차 하지 않는다.

## 보여주는 것

- **상단**: 총자산(현금+평가금액), 누적 수익률, 코스피 대비 초과수익률, **마지막 매매 실행 일시**
- **자산 추이 차트**: 총자산 vs 코스피 (시작값 기준 리베이스 — 기존 `charts._rebase` 재사용)
- **보유종목 테이블**: 종목명, 수량, 평단가, 최근 종가, 평가손익률
- **거래 내역 테이블**: 날짜, 종목, 매수/매도, 수량, 체결가, **판단 근거**(규칙 조건을 그대로 조립한 문장)
- **하단**: 오늘의 판단 요약(그날 매매 건수·자산 변동을 조립한 템플릿 문장)

## UI에서 반드시 말해줘야 하는 것

유저가 오해하기 쉬운 지점이 세 개 있고, 전부 화면에 명시한다:

1. **"실제 금전 거래가 아닌 시뮬레이션입니다. 투자 조언이 아닙니다."** — 기존 예측 기능의 경고보다
   더 눈에 띄게. 이 기능은 실제로 매수/매도를 자동 *실행*하므로 오해의 여지가 더 크다.
2. **"장중 실시간이 아니라 하루 1회 장 마감 후 자동 매매된 결과입니다."** — 안 적으면 유저가
   실시간 트레이딩으로 오해한다. 마지막 실행 일시를 상단에 띄우는 이유도 이것.
3. **체결가는 그날 종가 기준이라는 가정** — 거래내역 테이블 캡션 정도에 적는다.

또한 거래 근거(`reason`)는 **정해진 규칙에 따른 자동 판단 서술일 뿐 종목 추천이 아니라는 점**을 분명히 한다.
