# 에이전트 문서 색인

이 폴더에는 성격이 **완전히 다른 두 종류**의 "에이전트" 문서가 들어 있다. 같은 단어를 쓰지만
사는 곳도, 도는 시점도, 만드는 사람도 다르므로 섞어서 읽으면 안 된다.

| | ① 개발 에이전트 | ② 제품 에이전트 |
|---|---|---|
| **정체** | Claude Code 서브에이전트 | `src/`·`scripts/`에 있는 파이썬 코드 |
| **하는 일** | 이 저장소의 코드를 **만든다** | 대시보드 기능으로 **실행된다** |
| **도는 시점** | 개발자가 Claude Code로 작업할 때 | 매일 자동(GitHub Actions) / 방문 시(Streamlit) |
| **파일** | `메인_`, `코딩_`, `검증_` | `투자_` 로 시작하는 파일들 |
| **사용자에게 보이나** | 아니오 | 예 (매매 이력·자산 추이로) |

②를 만드는 것이 ①의 일이다. 즉 코딩 에이전트가 투자전략 에이전트의 코드를 작성한다.

---

## ① 개발 에이전트 — 이 저장소를 만드는 쪽

Claude Code 세션에서 역할을 나눠 일하는 서브에이전트들.

- **[메인 에이전트](./메인_에이전트.md)** — 사용자와 대화하고, 문제를 진단하고, 아래 둘에게
  작업을 위임한 뒤 결과를 재검증한다. 서버 재시작·테스트 실행 등 운영 작업도 직접 한다.
- **[코딩 에이전트](./코딩_에이전트.md)** — 메인의 지시를 받아 실제 코드를 고친다. 최소 diff
  원칙을 지키고, 고친 뒤 스스로 검증까지 마치고 보고한다.
- **[검증 에이전트](./검증_에이전트.md)** — 코드를 고치지 않고 버그만 찾는다. 헤드리스로 앱을
  구동해 여러 시나리오를 재현하고 구조적 위험까지 리뷰해서 보고한다.

## ② 제품 에이전트 — 모의투자 기능을 구성하는 쪽

**상태: 설계 완료, 구현 전.** 전체 설계 명세는 [PRD.md](../PRD.md)에 있고, 아래 문서들은
각 구성요소의 **역할·경계·책임**만 짧게 정리한 역할 카드다. 수치·스키마·프롬프트 같은
구체 명세는 PRD 한 곳에만 두고 여기서 중복하지 않는다 (두 군데 적으면 반드시 어긋난다).

실행 순서대로:

1. **[가격예측 에이전트](./투자_가격예측_에이전트.md)** — 후보 종목별 예측 신호를 만든다.
2. **[매매 규칙 엔진 + 리스크 가드레일](./투자_투자전략_에이전트.md)** — 신호에 임계값 규칙을
   적용해 매매를 제안하는 코드와, 그 제안을 다시 검증·승인하는 코드로 나뉜다. **V1은 LLM을
   쓰지 않는다** — 원래는 Claude가 판단하는 설계였으나 유료 서비스라 지금은 보류했고(PRD 9.1에
   원안 보존), 나중에 되살릴 수 있게 인터페이스만 유지해뒀다. (제안하는 쪽과 승인하는 쪽이
   분리돼 있는 것이 핵심 — LLM이 있든 없든 이 구조는 그대로다)
3. **[포트폴리오 원장](./투자_포트폴리오_원장.md)** — 현금·보유·거래이력·자산추이를 보관한다.
4. **[실행 스케줄러](./투자_실행_스케줄러.md)** — 위 1~3을 매일 자동으로 돌린다.
5. **[성과 리포팅 UI](./투자_성과리포팅_UI.md)** — 원장을 읽어서 보여주기만 한다.

**이 다섯의 관계를 한 줄로**: 1~4는 GitHub Actions에서 매일 한 번 돌고, 5는 그 결과를
방문자에게 보여준다. **5는 절대 1~4를 실행시키지 않는다** — 이 분리가 설계의 중심이다.
