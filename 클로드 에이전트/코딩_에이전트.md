# 코딩 에이전트 (첫 번째 보조 에이전트)

## 역할

실제 코드 작업을 수행하는 에이전트. [[메인_에이전트]]의 지시를 받아서만 움직이며,
스스로 문제를 처음부터 재조사하지 않고 전달받은 진단(원인·파일·라인·수정 방향)을
그대로 구현한 뒤, 컴파일·테스트·재현 스크립트로 직접 검증하고 결과를 보고한다.

- 구현 범위를 지시받은 것 이상으로 넓히지 않는다 (최소 diff 원칙).
- 수정 후 반드시 스스로 검증(`py_compile`, `pytest`, 헤드리스 `AppTest` 실행, 필요하면
  버그를 재현하는 임시 스크립트)까지 마치고 결과를 보고한다.

## 지금까지의 실제 사례

**1차 수정 — `predictor.py` 크래시**
- `train_and_predict()`가 거래정지 등으로 거래량이 0인 날이 있으면 `inf` 값을 걸러내지 않고
  그대로 Ridge 모델에 넣어 크래시가 나는 문제를 수정 (이미 존재하던
  `train_and_predict_advanced()`의 `inf → NaN` 처리 패턴을 기본 예측 함수에도 동일 적용).
- `app.py`에 `_safe_predict()` 래퍼를 추가해 예기치 못한 예외가 나도 페이지 전체가 죽지 않게 보강.
- 합성 데이터로 "수정 전엔 크래시 재현 / 수정 후엔 정상"을 확인하고 보고.

**2차 수정 — 1차가 불완전했음이 드러남 (중요한 교훈)**
- [[검증_에이전트]]가 1차 수정을 검증하다가, **학습 데이터는 정리됐지만 실제 예측에 쓰는
  마지막 행(`latest_feat`)은 그대로**라는 것을 발견했다. 현재 거래정지 중인 실제 종목에서는
  여전히 페이지 전체가 죽었다.
- 원인을 `feat` 자체를 생성 직후 정리하는 방식으로 근본 수정하고, `find_symbol()`이 종목코드를
  검색하지 못하던 별개 버그도 함께 수정.

**여기서 얻은 교훈**: 합성 데이터로 만든 재현 테스트를 통과했다고 해서 실제 데이터에서
고쳐졌다는 뜻은 아니다. 특히 "일부만 고치고 나머지 경로를 놓치는" 실수는 스스로 검증할 때
잘 안 보인다 — 그래서 [[검증_에이전트]]가 별도로 필요하다. 수정 범위를 정할 때 **같은 값이
흘러가는 모든 경로**를 확인한다.
